## The dominant question, and its answer

**A model API key cannot ship in browser code.** That single fact decides the deployment shape, and it was the one thing gating the build.

**Decision: a static site plus exactly one serverless function.** Not a pure static deploy, and not a server either.

```
index.html                      static
src/*.js                        static — screens, state, scoring
public/lesson.open-window.json  static — the authored lesson
api/coach.js                    the ONLY server-side code; holds the key
scripts/validate_lesson.py      offline gate, never runs at request time
```

The function receives performance data, makes the one model call, and returns the coaching note. Everything else in the product is a static asset.

**The detail that matters:** `api/coach.js` returns **HTTP 200 with a fallback body on any failure** — never a 4xx/5xx. A failed model call is not an error condition for this product; it is a degraded-but-complete ending. This satisfies PRD P0-9 ("if the coach call fails, the verdict must still render") at the transport layer rather than leaving it to client error handling.

## 1. Deployment — Vercel

**What this is:** where the product lives so a judge can click a link.

Chosen because it gives static hosting and key-holding serverless functions in one place with near-zero config, deploys on git push, and this session has Vercel tooling available to do the project setup and environment variables directly.

**Alternates considered:** Cloudflare Pages + Workers (generous free tier, very fast edge functions, slightly more config, no tooling here). Netlify (comparable, no advantage unless already in use).

**Not chosen:** any long-running server, container, or app framework. Nothing in the product needs one.

**Setup actions:**
- [ ] Create the Vercel project
- [ ] Set the model API key as a Vercel environment variable — **never in the repo, never in client code**
- [ ] Confirm the deployed link works from a clean browser and a phone

## 2. Frontend — vanilla, comps stay reference

**The situation:** the twelve approved comps are generated by a Python script emitting absolutely-positioned, inline-styled HTML at a fixed 1440×900. That is a comp technique. It was never the app, and the user's Phase-2 choice was explicitly "pictures to approve, rebuild later."

**Decision: build the app in semantic HTML with CSS Grid/Flexbox and vanilla JS modules.** Porting to React/Vue/Svelte does not solve the fixed-position problem — it adds a toolchain and a migration on top of it.

Skip a bundler unless something demands one. Every tool is another place to lose minutes.

**Screen routing:** one shell, eleven views toggled by a `data-screen` attribute on `<body>`, with hash-based URLs so a judge can be dropped mid-flow if needed.

**Reading measure:** the excerpt must be set at a real reading measure (65–75ch) and a fluid size, not the comp's fixed pixel values — PRD accessibility requires legibility as a functional property, and the comps are a 1440×900 still.

## 3. Session state — `localStorage`

**What has to survive:** current screen, first-attempt record per item, comprehension score, cited clues, collected vocabulary, reading start/end and WPM, right-answer-wrong-evidence count. For exactly one playthrough. No accounts, no server, no database.

**Decision: `localStorage`, with an in-memory mirror and a visible "Start Over".** Chosen over `sessionStorage` specifically for demo safety — an accidental refresh mid-recording must not wipe the run.

**The scoring rule that must be enforced in the state layer, not the UI:** a first attempt at an item increments both `possible` and (if correct) `correct`, and is then immutable. Every later attempt appends to a history and may flip `solved`, but can never touch the first-attempt figures. PRD P0-7 lives or dies here.

**Edge cases to handle:**
- Refresh mid-read → offer "Resume reading" rather than silently restarting the timer
- Back button → hash routing, or disable it
- Retry → never mutates a recorded score

## 4. The coach's model — Gemini Flash-Lite, and why the first two recommendations were both wrong

**This choice was researched after the user correctly identified vendor bias on both sides:**

- Claude was recommended by this session, which operates under a standing instruction to default to the latest Claude models when building AI applications. That is a bias, disclosed.
- OpenAI's `gpt-5-mini` was recommended by the council, which runs on OpenAI's own model.

**Neither recommendation survived the one fact that matters: there is no API key for any provider yet.** Web research found that as of September 2026 **neither Anthropic nor OpenAI offers a free API tier** — both are effectively prepaid, so either choice requires adding a card and topping up before a single call can be made, at hour 26 of 26.

**Google AI Studio issues a Gemini API key instantly, with no credit card, in all supported regions.**

Decision criteria, in the order they actually matter here:

1. **Can a key exist in the next ten minutes** → only Google (also Groq, Cerebras, OpenRouter, Cloudflare Workers AI, NVIDIA NIM)
2. **Schema-constrained JSON output** → Gemini has native `responseSchema` + `responseMimeType`, which is the shape the `/api/coach` design needs
3. **Latency at the demo's emotional peak** → Flash class is the fastest tier
4. **Cost for one short call per playthrough** → free

**Recommendation: Gemini Flash-Lite** (`gemini-3.5-flash-lite` or current equivalent).

**Caveats, stated because the sources disagree:**
- Free-tier request limits vary sharply by model and across sources — roughly 20 requests/day was quoted for top-end Flash models, ~500/day for Flash-Lite, and 1,500 RPD elsewhere. **Verify the real limit in AI Studio before depending on it.** Flash-Lite is the safer pick because dev-and-test traffic will exceed a 20/day cap long before the demo.
- Pro-tier models were removed from the free tier on 1 April 2026. Do not reach for those.

**Standing override:** if an OpenAI or Anthropic key already exists somewhere, use it. This is one short call on structured data; the model is close to the least consequential decision in the build, and a key in hand beats any model comparison at 25 hours.

**What the coach is sent — and this is a product guarantee, not an implementation detail:** missed-first-attempt items with their skill cluster and where in the excerpt the proving line sat, skill-cluster summary, pace (flagged as shown-not-graded), and the right-answer-wrong-evidence count. **Never** story text, excerpt text, line contents, or any explanation containing Saki's words. This is what makes a live model call safe inside a product that bans AI-written content, and the Case Report says so to the reader.

## 5. Coach fallback — three tiers

Phase 1 declined a pre-computed fallback. **That decision is reversed here**, on the council's argument and the user's agreement: the coach lands at the demo's emotional peak, and a spinner or error there makes the whole product feel fragile.

1. **Live model response** via `/api/coach`
2. **Deterministic response** keyed off the skill clusters — a real coaching note, chosen by rule, not a shrug
3. **Generic "case closed"** message as the last resort

Client-side: `AbortController` with a ~4.5s timeout, and the same fallback ladder mirrored locally so even a total network failure produces tier 2 rather than tier 3.

This is the honest implementation of PRD P0-9, not new scope.

## 6. TTS — cut

**Decision: no runtime TTS.** Captions only, as the PRD's pre-committed fallback already specified. Cutting it removes another API key, autoplay handling, audio loading states, sync complexity, and a failure mode during a recorded demo.

**Recorded for later:** if word timings are ever wanted, ElevenLabs offers TTS with character-level timestamps and a forced-alignment endpoint. OpenAI's speech endpoint generates audio but its documented word-timestamp support is on *transcription*, not generation. Worth knowing; not worth 25 hours.

## 7. Lesson authoring and validation — extend what works

**Decision: keep the existing Python model and add one command a judge could run.**

A working model already exists from the comp build (`scratchpad/gen/source.py`): it holds the 1–132 line numbering, contiguous `span()` extraction, `find()` by phrase with a character-offset map, `quote()` that raises on any phrase absent from the source, and derived excerpt provenance. **This must be copied into the repo before the scratchpad is lost** — it is the substrate of the PRD's P0-2 guarantees and it has already caught two real bugs.

Validation must assert:
- Excerpts reconstruct exactly to source, character for character
- Every cited line resolves, and sits inside its own excerpt
- Line numbering is continuous 1–132 and identical across every screen
- A phrase lookup resolves to the line the phrase *starts* on, including across a line break — **this was a live defect that silently attached citations to the wrong line**
- No authored question embeds paraphrase presented as source text

Run it as a named command, and wire it into the build so a violation fails the build rather than reaching a reader:

```bash
python3 scripts/validate_lesson.py public/lesson.open-window.json
```

Known normalisation traps to cover: curly vs straight quotes, `---` em dashes, double spaces after sentences, blank lines, excerpt boundary off-by-one.

**Python 3.9.6 is sufficient** for this. No new dependencies, no `uv`, no pandoc — the EPUB was already parsed and the plain text is in the repo.

## Architecture in plain language

A reader opens the link and gets a set of static files — the screens, the styling, and one JSON file holding the whole authored lesson. Everything they do, from turning the word lock to citing a line, happens in their own browser, and their progress is kept in that browser's own storage. Nothing is sent anywhere and there is nothing to log into.

At the very end, and only then, the browser sends a small summary of *how they performed* — never a word of the story — to a single small piece of code running on Vercel. That code is the only place the API key exists. It asks the model for one coaching note and hands it back. If anything at all goes wrong, it hands back a pre-written note instead, and the reader still gets their verdict.

The lesson file is built and checked on the author's machine before any of this ships, by a script that proves every word came from the book.
